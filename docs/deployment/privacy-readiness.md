# 隐私就绪、保留与生产发布操作手册

> 当前状态：**未就绪、未开放收集**。本手册记录未来生产候选环境的人工操作与证据要求，不表示专用隐私邮箱、腾讯云 Lighthouse、Nginx、独立容器入口或流量切换已经创建或启用。

## 适用范围与原则

本手册适用于 `/contact`、`/privacy` 和 `/api/contact` 的生产发布。代码中的就绪 evaluator 与 `release:check` 只能校验配置格式、绑定关系和人工证明是否被显式提供，不能证明邮箱、服务商、权限、删除流程或基础设施事实真实存在。

- 未完成全部人工证据时，联系页和 API 必须保持 fail-closed。
- 生产秘密只注入候选运行时，不进入外部构建、文档、日志或工单正文。
- 操作证据保存于受控的发布记录或秘密管理系统，不写入仓库。
- 每次服务版本、站点 Origin、公开隐私事实或 EdgeOne 事实变化，都必须重新计算快照并重新证明。

## 1. 创建专用邮箱并核验服务提供方

1. 创建专用隐私权利邮箱；不得使用个人邮箱、聊天工具或临时转发地址代替。
2. 分别确认并记录以下实际服务角色，不因它们可能属于同一供应商而合并证据：
   - 网站托管服务商、产品和数据处理位置；
   - SMTP 中继服务商和数据处理位置；
   - 联系信息收件邮箱服务商和存储位置；
   - 隐私权利邮箱服务商和存储位置。
3. 确认邮件处理位置位于中国大陆。存在境外处理路径时停止发布，另行进行设计和合规评审。
4. 为隐私邮箱、联系邮箱和运维管理账户启用多因素认证（MFA）。
5. 按最小权限分配邮箱管理员、联系信息处理人员、隐私权利处理人员和发布操作员；记录批准人、角色、开通时间及定期复核时间。
6. 禁止将联系邮件不受控地转发到个人邮箱、聊天工具、本地表格或未登记的副本位置。

完成以上核验后，才能填写相应的公开隐私事实；配置键和值的用途见项目根目录 `.env.example`。不要把真实值复制到本手册。

### evaluator 常用严格格式提示

以下提示集中说明容易误配的机器校验边界；完整规则始终以当前 evaluator 和 `.env.example` 为准，不要在文档中记录或猜测生产值。

- `SMTP_PORT` 规范化后只接受精确字符串 `465` 或 `587`，不接受其他端口、后缀或小数形式。
- `PRIVACY_SMTP_RELAY_LOCATION`、`PRIVACY_CONTACT_MAILBOX_LOCATION`、`PRIVACY_RIGHTS_MAILBOX_LOCATION` 必须以“中国大陆”开头；托管位置与 EdgeOne 日志位置仍按各自实际事实填写，不能套用该规则伪造。
- `PRIVACY_POLICY_EFFECTIVE_DATE` 必须是有效的 `YYYY-MM-DD`，且不得晚于 evaluator 执行时的北京时间当天。
- 专用隐私邮箱、投递邮箱、`SMTP_FROM`、SMTP 主机名和站点 Origin 必须通过实现中的严格语法校验。站点 Origin 必须是精确 HTTPS Origin，不得包含用户名、密码、路径、查询或片段。

## 2. 通过现有邮件适配器执行非个人信息投递探针

人工证明创建前，必须验证真实 SMTP 中继与目标邮箱之间的投递链路。

1. 在隔离的候选运行时注入真实 SMTP 与收件配置。
2. 使用只包含虚构标识的探针内容，例如随机 probe ID；不得使用真实姓名、手机号、邮箱、案件或业务材料。
3. 探针必须调用仓库现有的 `lib/mail.ts` `sendContactEmail` adapter。不得用另一份 Nodemailer 实现、原始 SMTP 命令或个人邮件客户端替代。
4. 当前仓库没有面向生产运维的投递探针 CLI。独立部署工作必须提供一个受控、一次性的 adapter 调用入口；在该入口及其执行证据存在前，本步骤不得勾选完成。
5. 核对发件地址、目标邮箱、TLS 投递结果和收件时间；不得在日志中打印 SMTP 凭据或原始 SMTP 响应。
6. 从收件箱、已发送、垃圾箱／回收站、可恢复项目和探针过程中产生的受控副本中删除测试邮件，并记录删除人、时间和 probe ID。

记录服务商侧投递事件 ID 时，只保存非个人信息标识；不要复制邮件正文或凭据。

## 3. 联系信息分类、保留与删除

受控邮箱工作流必须使用以下互斥或可审计的标签：

- `unconverted`：尚未转为正式项目的咨询；
- `contracted`：已签约或已转入正式业务记录的咨询；
- `rights-request`：隐私权利请求及处理记录。

### 未转化咨询

1. 使用服务端时间戳和 `requestId` 作为留存核对键。
2. 自提交日起不超过 180 天，删除收件箱、已发送、垃圾箱／回收站、可恢复项目、受控导出和受控副本中的未转化咨询。
3. 记录每次定期删除的范围、执行人、时间、结果和异常；不得把正文复制到删除证明。

### 已签约咨询

仅将正式业务所必需的信息转入受控业务记录，并改用合同约定和适用法定义务的留存规则。原始咨询中与业务无关的数据仍按最小化原则删除。

### 服务商备份和归档

取得并保存服务商对删除、回收站、可恢复项目、归档和备份到期机制的证据，记录实际到期周期和删除方法。无法立即从备份物理删除时，必须将处理限制为存储和安全用途，直至服务商周期届满。没有该证据时不得创建运营证明。

因法律义务、争议处理或提出、抗辩法律主张确需继续保存时，只在必要范围和期限内限制使用，并记录适用依据。

## 4. 隐私权利请求

1. 只通过已核验的专用隐私邮箱受理请求。
2. 在受控邮箱工作流中记录收到时间、核验方式、处理动作、结果和完成时间。
3. 使用最少附加信息核验身份：优先验证请求人对原咨询所用邮箱或手机号的控制权，并结合 `requestId` 或足以定位记录的非敏感提交上下文。
4. 常规核验不得索取身份证件副本、生物识别材料、金融账户或健康信息。
5. 确有必要加强核验时，必须取得主管批准并记录书面必要性理由；核验材料在核验完成后立即删除，只保留非敏感的核验结论。
6. 从身份核验完成后起算，在 15 个工作日内答复。确需延长时，告知原因和预计完成时间。
7. `rights-request` 处理记录在结案后最多保留 180 天，随后从所有受控邮箱位置和副本删除；法律义务或争议处理另有要求的除外。
8. 本阶段不得为权利请求新建应用数据库。

## 5. Lighthouse/Nginx 与应用日志

以下配置属于独立部署工作，必须在候选环境逐项检查并保存实际配置片段、命令输出或截图证据。

### Nginx 请求与缓存边界

- 对 `/api/contact` 设置 `client_max_body_size 16k`。
- 访问日志格式不得包含 `$request_body`、表单字段或请求正文；错误日志也不得主动输出正文。
- 记录 `proxy_request_buffering` 及相关 buffering/streaming 的实际配置。分别用普通 JSON、分块／流式请求和超过 16 KiB 的请求执行 smoke test，记录请求由 Nginx 还是应用拒绝、状态码及是否到达应用；不得把探针正文写入证据。
- 对 `/contact`、`/privacy` 和 `/api/contact` 配置缓存旁路，不在 Nginx 或上游缓存这些响应；验证 `Cache-Control: private, no-store, max-age=0` 未被覆盖。
- 将 Nginx 访问日志配置为 30 天轮转和删除，并验证旧文件、压缩文件及外部日志副本同样到期删除。

### 应用日志

- 应用日志只允许 `requestId`、结果码、HTTP 状态和耗时等粗粒度元数据。
- `requestId` 可关联到具体联系邮件，应按技术个人信息管理；应用日志在 30 天内删除。
- 禁止记录姓名、手机号、邮箱、机构、链接、留言、表单正文、隐私配置值、SMTP 凭据或原始 SMTP 错误／响应。
- 日志导出、告警和备份必须遵守同一 30 天期限，不能通过复制延长保留。

## 6. 快照、人工证明和候选发布顺序

严格按以下顺序执行，不得先切流再补证明：

1. 完成邮箱、服务提供方、权限、MFA、删除／备份、非个人信息投递探针、Nginx 和日志检查。
2. 在待发布的公开事实环境中运行 `npm run privacy:snapshot`。该命令只允许输出 64 位小写十六进制公共快照哈希，不输出任何配置值。
3. 为候选版本生成不可变的 `SERVICE_VERSION_ID`。
4. 由受限发布操作员创建人工证明，记录证明 ID、负责人和 ISO 8601 批准时间；批准时间不得位于未来。
5. 确认以下绑定：
   - `PRIVACY_ATTESTED_SERVICE_VERSION_ID` 等于当前不可变 `SERVICE_VERSION_ID`；
   - `PRIVACY_ATTESTED_SITE_ORIGIN` 等于规范化后的当前 `NEXT_PUBLIC_SITE_URL` Origin；
   - `PRIVACY_ATTESTED_PUBLIC_SNAPSHOT_ID` 等于步骤 2 的当前公共快照。
6. 通过腾讯云 IAM 与服务版本发布流程限制证明和生产运行时变量的写权限；开发者或普通邮箱处理人员不得自行批准。
7. 构建产物时不注入生产 SMTP 秘密。将生产变量和人工证明注入候选运行时后，在该候选环境运行 `npm run release:check`。
8. 只有 `release:check` 退出码为 0 时才允许切换流量；非零输出仅可包含 issue code 和配置键名，不得包含值。
9. 切流后复核 `/contact`、`/privacy`、`/api/contact` 的状态、metadata、no-store 响应和一封合成咨询邮件；核对邮件中的 `requestId`、服务端时间、政策版本、日期和快照，再删除探针邮件。

服务版本、Origin、公开事实或证明绑定发生变化时，旧证明立即失效，必须从快照步骤重新执行。

## 7. 当前基础设施状态与独立部署边界

腾讯云 Lighthouse 北京地域 2 核 CPU／2 GB 内存是当前选定的目标方案，**尚未创建或验收**。以下工作不由本次文档或隐私代码变更完成：

- 创建和加固 Lighthouse、容器及非 root 运行环境；
- 生成 Next.js standalone 产物；
- 配置和发布 Nginx、日志轮转与三路径缓存旁路；
- 实现候选容器健康检查与原子流量切换；
- 创建 future standalone entrypoint。

未来 standalone 以 `node server.js` 启动时不会自动触发 npm `prestart`，因此容器 entrypoint 必须先运行同一个 `release:check`，成功后才能启动服务。该 entrypoint 与流量切换机制存在并经过验收前，不得宣称基础设施级发布门禁已经完成。
